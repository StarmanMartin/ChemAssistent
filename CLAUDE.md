# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is
A small Ubuntu desktop app (Python 3, GTK 3 via PyGObject, VTE). A Chemotion icon in the GNOME top bar (Ayatana AppIndicator) opens a centered prompt; submitting it grows the window to the work area with the opencode TUI (in a `Vte.Terminal`) on the left and a result panel on the right. The opencode agent talks to the Chemotion ELN only through one MCP tool whose code the user must confirm in the result panel. Structure, config handling, settings app, install scripts and the opencode lookup are taken over from `~/Deveolop/private/vikunja-popups`. There are no tests, no linter config and no build step.

## Commands
- Run from the source tree: `.venv/bin/python app.py --show` (`--show` opens the prompt at start; a second start sends `{"type": "show"}` over the socket to the running instance instead).
  - The venv must be created with **`/usr/bin/python3`** `-m venv --system-site-packages .venv` (an asdf/pyenv `python3` on the PATH has no `gi`), then `.venv/bin/pip install -r requirements.txt` and `./setup_workspace.sh "$PWD" "$PWD/.venv/bin/python"`, which clones chemotionapi `version-3` into `workspace/chemotionapi`, pip-installs it and writes `workspace/CHEMOTION_API.md`. An optional third argument is an opencode skills dir: every `skills/<name>/` with a `SKILL.md` in the checkout replaces `<dir>/<name>` (both installers pass `~/.config/opencode/skills`; the Windows one `%USERPROFILE%\.config\opencode\skills`, because MSYS2's `$HOME` is not the Windows profile).
- Install: `./install.sh` (apt for missing packages, copies `APP_FILES` to `~/.local/share/chem-assistent/`, venv, `setup_workspace.sh`, opencode 2 via `https://opencode.ai/v2/install` if missing or older, `setup_opencode.py` (the `ki-toolbox` provider in `~/.config/opencode/opencode.json`, empty `ai_model` → `ki-toolbox/complex-local`), the `KI_TOOLBOX_API_KEY` prompt into `~/.config/environment.d/50-ki-toolbox.conf` (plus `systemctl --user import-environment`), desktop files from `*.desktop.in` with `@APP_DIR@` filled in, enables and starts `chem-assistent.service`). A new file must be added to `APP_FILES`.
- Windows (10/11 + MSYS2 UCRT64, untested on real Windows): `install.ps1` / `uninstall.ps1` (PowerShell 5.1, keep them ASCII-only; native-command probes with `2>$null` go through `Invoke-Probe` because PowerShell 5.1 with `Stop` turns redirected stderr into exceptions). It installs the pacman packages (incl. the compiled chemotion_api deps: jsonschema/rpds-py, yaml, `file` for libmagic), a venv with `--system-site-packages` (`bin\` or `Scripts\`), runs `setup_workspace.sh` through MSYS2's bash with `C:/` paths, the opencode v2 installer with `HOME` = `%USERPROFILE%`, `setup_opencode.py`, `KI_TOOLBOX_API_KEY` as user environment variable, Start-menu/Startup shortcuts to the venv's `pythonw.exe`. A new file must be added to `APP_FILES` in **both** `install.sh` and `install.ps1`.
- `setup_opencode.py` (both installers, stdlib only): adds the `ki-toolbox` provider to the user's opencode.json if missing and fills an empty `ai_model`. The plain `https://opencode.ai/install` only installs opencode 1; the app needs `https://opencode.ai/v2/install`.
- Settings app: `.venv/bin/python settings.py`. Logs: `journalctl --user -u chem-assistent.service -f`. Uninstall: `./uninstall.sh`.

## Architecture
- Platform split: `config.WINDOWS`. Windows has no VTE (`Vte` is `None` in app.py), no AppIndicator (`Gtk.StatusIcon`), no AF_UNIX in Python and no unix signals (`signal_add` is `None`). On Windows `main()` logs to `STATE_DIR/app.log`, writes the PID file (`app_control.py`, used by the settings' Start/Stop) and prepends the interpreter's and `sys.base_prefix/bin` to `PATH` (libmagic DLL). Child processes get `creationflags=NO_WINDOW`; stdio children (MCP server, runner) use `workspace.console_python()` (python.exe instead of pythonw.exe).
- `ipc.py`: the app's endpoint. Linux: Unix socket `SOCKET_PATH`, empty token. Windows: `127.0.0.1:<random port>` plus a random token, both in `ENDPOINT_FILE` (for a second start) and in the MCP server's environment (`CHEM_ASSISTENT_SOCKET`, `CHEM_ASSISTENT_TOKEN`); requests without the right token are dropped.
- `console_win.py` (Windows): opencode runs with `CREATE_NEW_CONSOLE` and `--prompt` (no terminal to paste into; the race lands in the restricted `build` copy). `AttachConsole` + `GetConsoleWindow` finds the console window, `MoveWindow` puts it left of the results window (`RESULTS_SHARE`; under Windows Terminal the window is a hidden stand-in and stays where it is). A 1 s timer polls the process for its end; closing runs `taskkill /T /F`. `.cmd` shims (npm) are refused because cmd.exe would interpret the prompt.
- `config.py`: `~/.config/chem-assistent/config.json` (Windows: `%APPDATA%`, state in `%LOCALAPPDATA%`) (0600, atomic writes), `load_config()` raises `ValueError` while URL/user/password are missing (`config_problem()`); `CHEMOTION_PASSWORD` overrides the password. The app starts anyway and reports problems in the prompt. `WORKSPACE_DIR` is `workspace/` next to the code; `SOCKET_PATH` is in `$XDG_RUNTIME_DIR` (AF_UNIX paths are limited to ~100 bytes).
- `gen_api_reference.py`: walks `docs/index.rst` of the chemotionapi checkout in toctree order, converts the reST lightly to Markdown and expands `autoclass`/`automodule`/`autoenum` with signatures and docstrings of the **installed** package (so it must run with the venv's Python). Install/docker-CLI sections are skipped (`SKIP_SECTIONS`).
- `workspace.py` writes `workspace/opencode.json` before every conversation (opencode v2 config format: `agents`, `permissions` = ordered `{action, resource, effect}` rules, last match wins, `mcp.servers`). Rules: deny `*`, allow `read`/`grep`/`glob`/`list`/`question` and `chemotion_execute_python` (MCP tool ids are `<server>_<tool>`), deny `external_directory`. The MCP server has `"codemode": false`, otherwise opencode v2 wraps MCP tools in its JavaScript `execute` tool. `plan` is disabled; `build` is a copy of the `chemotion` agent because the TUI uses `build` and opencode's default model for a message sent before it loaded the config (a disabled `build` silently drops it).
- opencode TUI details (v2.0.x): it has no `--agent`/`--model` flags and ignores the configured model in favor of `state/opencode/model.json` (recent models) and reopens the tabs of its last run. `tui_environment()` therefore gives it a private `XDG_STATE_HOME` (`~/.local/state/chem-assistent/opencode-state`) with only the configured model and deletes `latest/` (open tabs). The TUI is started with `--standalone` (the shared background service caches project config) and `PWD` set to the workspace. The prompt is **not** passed with `--prompt` (race, see above): `AssistantWindow._send_when_ready()` polls the terminal text until the footer shows `"Chemotion ·"` (`workspace.AGENT_LABEL`), then `paste_text()` + `\r`. Do not set `XDG_CONFIG_HOME` for the child: opencode would lose the user's providers and fall back to free models.
- `mcp_server.py` (no deps, newline-delimited JSON-RPC on stdio, nothing else may go to stdout): `initialize`, `tools/list`, `tools/call` for `execute_python`. A call connects through `ipc.connect()`, sends `{"type": "execute", "purpose", "code", "token"}` plus a newline (no half-close), and blocks until the app answers `{"ok", "text"}`. stdin/stdout are reconfigured to UTF-8 with bare `\n`. The tool timeout in opencode.json is 6 h because the call waits for the user.
- `app.py`:
  - `RequestServer`: accept thread plus one thread per connection; requests go to the main loop with `GLib.idle_add`. Each execute becomes a `PendingRequest` (a `threading.Event` the card sets via `answer()`). While waiting, the thread checks with `select()` + `recv(MSG_PEEK)` whether the MCP server closed the socket (opencode cancelled the call; it sends nothing after its request) and then marks the card abandoned.
  - `AssistantWindow`: one undecorated window; a `Gtk.Stack` with the prompt page and, after submit, the conversation page (header bar, `Gtk.Paned` with VTE + `ResultsPanel`). `_grow()` animates move/resize to `work_area()` and then maximizes. The window is DIALOG-type/keep-above while it is a prompt and drops keep-above/skip-taskbar when expanded. Escape closes only the prompt (in the conversation it belongs to opencode). Focus uses `GdkX11.x11_get_server_time()` because menu activations from the top bar arrive over D-Bus without an event time. Closing kills the TUI's process group with SIGHUP and rejects waiting cards.
  - `RequestCard`: editable code (GtkSourceView 4 if installed, else `TextView`), Run / Reject with optional reason, then a status line (the output goes to a result tab). `Execution` runs `chemotion_runner.py` with the venv Python in its own session (killable, `execution_timeout`), reading fresh credentials with `load_config()`. The answer to the agent says whether the user edited the code (and includes the code that ran), the output, `result` as JSON, clipped to `MAX_ANSWER_CHARS`.
  - `ResultsPanel`: a vertical `Gtk.Paned`; on top only the newest `RequestCard` (older cards stay only while waiting/running, `_prune()`), below a `Gtk.Notebook` with one tab per finished run (`result_page()`: output, error, result; at most `MAX_RESULT_TABS`).
  - `result_widget()`: list of dicts → table (max `MAX_TABLE_COLUMNS`), dict → key/value table, dict with list/dict values → one section per key, list of scalars → one column, else text. Dicts with a `"url"` (every element from the runner) are rows with a link icon that open the URL in the browser on a single click (`open_url()`, `webbrowser`).
  - Display: `GDK_BACKEND=x11` is forced whenever `DISPLAY` is set, because Mutter ignores client positioning on Wayland. The dark theme variant is requested. `gi.require_version("Gdk", "3.0")` is needed because Gdk is imported before Gtk.
  - Top bar: the GNOME AppIndicator extension never sends a plain left click to Ayatana indicators (left click opens the menu, middle click → `SecondaryActivate`), so the first menu entry “Ask Chemotion…” is also the secondary-activate target. The icon is `chem-assistent-panel.svg` found via `set_icon_theme_path(HERE)`. Without the AppIndicator typelib the app logs a warning and opens the prompt.
- `chemotion_runner.py`: stdin JSON → logs in (`Instance(url).test_connection().login()`), execs the snippet with `instance` predefined and stdout/stderr captured, `to_jsonable()` converts `result` (elements/collections/users become small dicts via `describe_object()`; elements get `url` from chemotionapi's `element.url()`; lists capped at `MAX_ITEMS`), JSON on stdout.
- `settings.py`: ordinary GTK window like vikunja-popups' settings (model combo from `opencode models` in a thread, “Test connection” logs in with chemotion_api in a thread, Start/Stop app through `app_control.py` = `systemctl --user` on `chem-assistent.service`). Saving needs no restart: the app reads the config per conversation.

## Testing notes
- A local Chemotion test instance from chemotionapi's `test_config` (docker, port 3579) is useful; its login is in `~/Deveolop/KIT/chemotionapi/tests/config.json`. Never commit credentials.
- Under rootless XWayland the root window cannot be captured; capture the app's own window with `Gdk.pixbuf_get_from_window(window.get_window(), ...)`.
- `opencode` commands run without `--standalone` in the workspace start MCP servers inside the user's shared background service.
