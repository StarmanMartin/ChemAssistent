# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is
A small Ubuntu desktop app (Python 3, GTK 3 via PyGObject). A Chemotion icon in the GNOME top bar (Ayatana AppIndicator) opens a centered prompt; submitting it grows the window to the work area with a chat (`ChatPanel`) on the left and a result panel on the right. The agent is our own (`agent.py`, stdlib only) and talks to any OpenAI-compatible API (default: the KIT KI-Toolbox); it reaches the Chemotion ELN only through its `execute_python` tool, whose code the user must confirm in the result panel. Structure, config handling, settings app and install scripts are taken over from `~/Deveolop/private/vikunja-popups`. Until 2026-10 the app embedded the opencode TUI instead (see git history). There are no tests, no linter config and no build step.

## Commands
- Run from the source tree: `.venv/bin/python app.py --show` (`--show` opens the prompt at start; a second start sends `{"type": "show"}` over the socket to the running instance instead).
  - The venv must be created with **`/usr/bin/python3`** `-m venv --system-site-packages .venv` (an asdf/pyenv `python3` on the PATH has no `gi`), then `.venv/bin/pip install -r requirements.txt` and `./setup_workspace.sh "$PWD" "$PWD/.venv/bin/python"`, which clones chemotionapi `version-3` (with its `skills/`) into `workspace/chemotionapi`, pip-installs it and writes `workspace/CHEMOTION_API.md`.
- Install: `./install.sh` (apt for missing packages, copies `APP_FILES` to `~/.local/share/chem-assistent/` and deletes `OLD_FILES` there, venv, `setup_workspace.sh`, `setup_ai.py`, desktop files from `*.desktop.in` with `@APP_DIR@` filled in, enables and starts `chem-assistent.service`). A new file must be added to `APP_FILES`.
- Windows (10/11 + MSYS2 UCRT64, untested on real Windows): `install.ps1` / `uninstall.ps1` (PowerShell 5.1, keep them ASCII-only; native-command probes with `2>$null` go through `Invoke-Probe` because PowerShell 5.1 with `Stop` turns redirected stderr into exceptions). It installs the pacman packages (incl. the compiled chemotion_api deps: jsonschema/rpds-py, yaml, `file` for libmagic), a venv with `--system-site-packages` (`bin\` or `Scripts\`), runs `setup_workspace.sh` through MSYS2's bash with `C:/` paths, `setup_ai.py`, Start-menu/Startup shortcuts to the venv's `pythonw.exe`. A new file must be added to `APP_FILES` in **both** `install.sh` and `install.ps1`.
- `setup_ai.py` (both installers, run from the source dir with the system Python, stdlib only): `read_raw_config()` fills `ai_url`/`ai_model` defaults and maps opencode-era ids (`ki-toolbox/<x>`, `config.LEGACY_MODELS`); an empty `ai_token` is taken from `KI_TOOLBOX_API_KEY` (install.sh first reads it from the old `~/.config/environment.d/50-ki-toolbox.conf`, install.ps1 from the user environment) or asked for with `getpass` on a tty.
- Settings app: `.venv/bin/python settings.py`. Logs: `journalctl --user -u chem-assistent.service -f`. Uninstall: `./uninstall.sh`.

## Architecture
- Platform split: `config.WINDOWS`. Windows has no AppIndicator (`Gtk.StatusIcon`), no AF_UNIX in Python and no unix signals (`signal_add` is `None`). On Windows `main()` logs to `STATE_DIR/app.log`, writes the PID file (`app_control.py`, used by the settings' Start/Stop) and prepends the interpreter's and `sys.base_prefix/bin` to `PATH` (libmagic DLL). The runner gets `creationflags=NO_WINDOW` and `workspace.console_python()` (python.exe instead of pythonw.exe). Otherwise the UI is the same on both platforms.
- `ipc.py`: only for a second start of the app (`{"type": "show"}`). Linux: Unix socket `SOCKET_PATH`, empty token. Windows: `127.0.0.1:<random port>` plus a random token, both in `ENDPOINT_FILE`; requests without the right token are dropped.
- `config.py`: `~/.config/chem-assistent/config.json` (Windows: `%APPDATA%`, state in `%LOCALAPPDATA%`) (0600, atomic writes), `load_config()` raises `ValueError` while URL/user/password are missing (`config_problem()`); `CHEMOTION_PASSWORD` overrides the password. AI: `ai_url` (default `KI_TOOLBOX_URL`), `ai_token` (empty → env `KI_TOOLBOX_API_KEY`, `ai_token()`), `ai_model` (default `alias.complex-local`); `ai_problem()` is checked on submit and in the settings. The app starts anyway and reports problems in the prompt. `WORKSPACE_DIR` is `workspace/` next to the code; `SOCKET_PATH` is in `$XDG_RUNTIME_DIR` (AF_UNIX paths are limited to ~100 bytes).
- `gen_api_reference.py`: walks `docs/index.rst` of the chemotionapi checkout in toctree order, converts the reST lightly to Markdown and expands `autoclass`/`automodule`/`autoenum` with signatures and docstrings of the **installed** package (so it must run with the venv's Python). Install/docker-CLI sections are skipped (`SKIP_SECTIONS`).
- `workspace.py`: `SYSTEM_PROMPT` (an f-string formatted again with `skills=`, so literal braces are quadrupled) plus `skill_lines()`, which lists `workspace/chemotionapi/skills/*/SKILL.md` with the `description` from their front matter; the agent reads them on demand.
- `agent.py` (no GTK, stdlib `urllib` only, standard OpenAI-compatible endpoints only): `list_models()` = `GET /models` (Open WebUI's `info.meta.hidden` models dropped; the KI-Toolbox needs ~15 s for it). `Agent.send()` runs in a worker thread: streamed `POST /chat/completions` with `tools`, SSE parsing (falls back to a plain JSON answer), tool-call deltas merged by `index`, `reasoning_content` kept and sent back (DeepSeek), at most `MAX_ROUNDS` tool rounds per message. Tools: `execute_python` (callback into the app, blocks until the user decides), read-only `read_file`/`grep`/`list_files` confined to `Agent.roots` (`_resolve()`: `WORKSPACE_DIR` plus every attachment of the conversation; relative paths are workspace paths, attachments are addressed by absolute path; binary files are only described). `send(text, attachments)` adds the attachments to `roots` and appends their absolute paths with `describe_attachment()` to the user message. Events go out through `on_event(kind, data)`: text/thinking/tool/done/error/stopped. `cancel()` closes the HTTP response; `_close_open_calls()` answers every unanswered tool call, or the next request is refused. Tested with the KI-Toolbox's `alias.complex-local` (GLM), `alias.medium-local` (DeepSeek), `alias.complex-gpt` and `alias.complex-claude`.
- `app.py`:
  - `RequestServer`: accept thread for ipc.py (only `show`). `PendingRequest`: one `execute_python` call, a `threading.Event` the card sets via `answer()`; `AssistantWindow._execute()` (agent thread) waits on it and abandons it when the agent is cancelled.
  - `AssistantWindow`: one undecorated window; a `Gtk.Stack` with the prompt page and, after submit, the conversation page (header bar, `Gtk.Paned` with `ChatPanel` + `ResultsPanel`, `CHAT_SHARE`). `_grow()` animates move/resize to `work_area()` and then maximizes. The window is DIALOG-type/keep-above while it is a prompt and drops keep-above/skip-taskbar when expanded. Escape closes the prompt, and in the conversation stops a busy agent. Agent events reach the main loop through `GLib.idle_add` (`_on_agent_event`); `closed` guards events after the window is gone. Focus uses `GdkX11.x11_get_server_time()` because menu activations from the top bar arrive over D-Bus without an event time. Closing cancels the agent and rejects waiting cards.
  - `ChatPanel`: messages in a scrolled box (`BottomFollower` keeps it at the bottom), streamed answers re-rendered at most every 60 ms with `markdown_markup()` (code blocks, aligned tables, headings, lists, inline code, bold, links → Pango markup; validated with `Pango.parse_markup`, else plain text), notes for tools and code cards, status line with spinner, multi-line input (Enter sends, Shift+Enter newline), Send/Stop, a paperclip `Gtk.MenuButton` (File…/Folder… via `Gtk.FileChooserNative`) and drag and drop of `text/uri-list` onto the panel (the text view's own drop target is unset) collect attachments as chips in a `Gtk.FlowBox`; they go with the next message.
  - `RequestCard`: editable code (GtkSourceView 4 if installed, else `TextView`), Run / Reject with optional reason, then a status line (the output goes to a result tab). `Execution` runs `chemotion_runner.py` with the venv Python in its own session (killable, `execution_timeout`), reading fresh credentials with `load_config()`. The answer to the agent says whether the user edited the code (and includes the code that ran), the output, `result` as JSON, clipped to `MAX_ANSWER_CHARS`.
  - `ResultsPanel`: a vertical `Gtk.Paned`; on top only the newest `RequestCard` (older cards stay only while waiting/running, `_prune()`), below a `Gtk.Notebook` with one tab per finished run (`result_page()`: output, error, result; at most `MAX_RESULT_TABS`).
  - `result_widget()`: list of dicts → table (max `MAX_TABLE_COLUMNS`), dict → key/value table, dict with list/dict values → one section per key, list of scalars → one column, else text. Dicts with a `"url"` (every element from the runner) are rows with a link icon that open the URL in the browser on a single click (`open_url()`, `webbrowser`).
  - Display: `GDK_BACKEND=x11` is forced whenever `DISPLAY` is set, because Mutter ignores client positioning on Wayland. The dark theme variant is requested. `gi.require_version("Gdk", "3.0")` is needed because Gdk is imported before Gtk.
  - Top bar: the GNOME AppIndicator extension never sends a plain left click to Ayatana indicators (left click opens the menu, middle click → `SecondaryActivate`), so the first menu entry “Ask Chemotion…” is also the secondary-activate target. The icon is `chem-assistent-panel.svg` found via `set_icon_theme_path(HERE)`. Icons: the Chemotion mark (two open rings as exact arc paths, the red "c" traced from the original PNG) in `chem-assistent.svg` (dark-gray outer ring; desktop/menu, window icon, Windows .ico and tray, `docs/assets/logo.svg`) and `chem-assistent-panel.svg` (light outer ring `#e6e6e6`; top bar, the app's dark prompt/header via `DARK_UI_ICON_FILE`, the presentation's cover slide inline). Keep them in sync. Without the AppIndicator typelib the app logs a warning and opens the prompt.
- `chemotion_runner.py`: stdin JSON → logs in (`Instance(url).test_connection().login()`), execs the snippet with `instance` predefined and stdout/stderr captured, `to_jsonable()` converts `result` (elements/collections/users become small dicts via `describe_object()`; elements get `url` from chemotionapi's `element.url()`; lists capped at `MAX_ITEMS`), JSON on stdout.
- `settings.py`: ordinary GTK window like vikunja-popups' settings (Chemotion fields; AI section with `ai_url` combo offering the KI-Toolbox URL, secret `ai_token`, `ai_model` combo filled by “Load models” = `agent.list_models()` in a thread, which also tests URL and token; “Test connection” logs in with chemotion_api in a thread; Start/Stop app through `app_control.py` = `systemctl --user` on `chem-assistent.service`). Saving needs no restart: the app reads the config per conversation.

## Testing notes
- A local Chemotion test instance from chemotionapi's `test_config` (docker, port 3579) is useful; its login is in `~/Deveolop/KIT/chemotionapi/tests/config.json`. Never commit credentials.
- Under rootless XWayland the root window cannot be captured; capture the app's own window with `Gdk.pixbuf_get_from_window(window.get_window(), ...)`.
